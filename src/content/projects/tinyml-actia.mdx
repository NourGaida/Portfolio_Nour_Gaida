## Problem and motivation

A NILM model is only useful in a home if it runs close to the meter, without sending raw consumption data to the cloud. The goal of this part of the internship was to take the trained models from the NILM project and make them run on an embedded platform, the STM32MP157F-DK2.

## Technical approach

- **Model conversion.** The disaggregation and novelty-detection models are converted to TFLite for inference on the board.
- **On-device fine-tuning.** The module `auto_finetune_nilm_v7.py` adapts the BiLSTM v7 model to a new house. It was written around the documented constraints of the project: the target hardware, the 18-appliance output layout and the per-appliance validity masks.
- **Novelty detection on the edge.** The convolutional autoencoder runs next to the disaggregation model to flag unknown appliances.

## Dataset and preprocessing

Fine-tuning datasets for new houses are built from the same UK-DALE/NILMTK pipeline as the main project, with `_valid` mask columns marking which appliances are actually present in a given house.

## Challenges and lessons learned

- Designing the model with the target hardware in mind from the start avoids a painful conversion step later.
- Fine-tuning on the device only works if the data pipeline for a new house is automatic, which is why the validity masks and the metadata parsing were built into the dataset creation.
